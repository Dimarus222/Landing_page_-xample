# CLAUDE.md — инструкция для ИИ-агента по проекту KERNEL

Этот файл читает ИИ-агент (Claude Code, Cursor, любой другой ассистент), которому поручат дорабатывать этот
репозиторий. Если ты — ИИ-агент и читаешь это: пожалуйста, следуй разделу **«Правило живой документации»** в
конце файла при любых изменениях.

## 0. Контекст проекта одним абзацем

KERNEL — статический (без бэкенда) образовательный сайт-учебник по компьютерной безопасности, размещённый на
GitHub Pages. У владельца проекта нет бюджета на сервер, поэтому **любое** предложенное решение должно работать
как чистый статический сайт (HTML/CSS/JS) либо опираться исключительно на бесплатные serverless-сервисы.
Не предлагай и не пиши код на Go/Python/Node-бэкенд, который требует постоянно работающего сервера, если только
владелец явно не скажет, что бюджет на хостинг появился.

## 1. Плоская структура репозитория — это осознанное решение

Все файлы лежат в корне репозитория без подпапок (кроме случаев, когда подпапка технически неизбежна, например
`.github/workflows/`, которого сейчас в проекте нет и добавлять не нужно без явного запроса). Это сделано
специально для простоты: владелец загружает файлы на GitHub без необходимости разбираться со структурой
директорий. **Не превращай структуру обратно в `css/`, `js/`, `js/data/` и т.п. без явного запроса владельца.**
Если добавляешь новый файл — клади его в корень с понятным именем (`data-<тема>.js`, `<фича>.js` и т.д.) и
подключай в `index.html` прямым путём вида `<script src="имя-файла.js"></script>`.

## 2. Архитектура

- `index.html` — разметка. Секции: мобильный топбар, боковое меню (`#sidebar`), основная область контента
  (`#content` → `#lesson-render`), тост достижений (`#achievement-toast`).
- `style.css` — все стили. В `:root` — CSS-переменные (design tokens) темы `dark` по умолчанию. Темы `matrix`
  и `sepia` переопределяют переменные через `[data-theme="matrix"]` / `[data-theme="sepia"]`.
- `app.js` — вся логика на чистом JS (без фреймворков, без сборки). Ключевые части:
  - `collectSemesters()` — собирает семестры из `window.__KERNEL_SEMESTERS`, куда каждый `data-*.js` пушит себя
    сам при загрузке (см. ниже).
  - `LS_KEYS` — все ключи localStorage. Есть `LEGACY_LS_KEYS` и `migrateLegacyStorage()` — механизм переноса
    прогресса пользователей со старых версий сайта (SecOpticon). **Если снова переименуешь бренд/ключи —
    добавь аналогичную миграцию**, не ломай прогресс существующих пользователей.
  - `loadLesson()` — рендерит урок: хлебные крошки, оглавление, сам HTML урока, панель заметок, банки
    литературы/ссылок, кнопки навигации.
  - `renderRoadmap()`, `renderGlossary()`, `renderContinueScreen()` — альтернативные экраны в `#lesson-render`.
  - `openCommandPalette()` — быстрый поиск по `Ctrl/⌘+K`.
  - `checkAchievements()` / `ACHIEVEMENT_DEFS` — система достижений; чтобы добавить новое достижение, просто
    добавь объект `{ id, icon, title, desc, check(ctx) }` в массив.
- `data-law.js`, `data-math.js`, `data-cs.js`, `data-os-net.js`, `data-crypto.js`, `data-websec.js` — контент
  семестров 0–5. Каждый файл — самостоятельный модуль (IIFE), который в конце делает:
  ```js
  if (!window.__KERNEL_SEMESTERS) window.__KERNEL_SEMESTERS = [];
  window.__KERNEL_SEMESTERS.push({ id: <номер>, data: <объект семестра> });
  ```
  **Это критично.** В версии до рефакторинга семестр 2 (`data-cs.js`, тогда `js/data/s2-cs.js`) не содержал
  этой регистрации и был из-за этого невидим на сайте — это был баг, он исправлен. Если копируешь файл как
  шаблон для нового семестра — проверь, что регистрация в конце файла есть.

## 3. Формат данных семестра и урока

```js
{
  id: 6,                       // числовой ID семестра, должен быть уникальным
  title: "🔍 Форензика",       // с эмодзи-иконкой — так выглядит в дереве и на карте обучения
  motto: "Расследование",      // короткий девиз для карты обучения
  lessons: [
    { id: "6.1", title: "Название урока", type: "forensics", content: "<h1>...</h1>..." }
  ],
  literature: ["Автор «Книга», год"],   // список строк
  links: [{ t: "📘 Название ссылки", u: "https://..." }]
}
```

`content` — это **готовый HTML-фрагмент** урока (не Markdown). Используй хелперы `L()` и `makeContent()`,
скопировав паттерн из любого существующего `data-*.js` файла, чтобы не плодить неконсистентный код.

### Семантические CSS-классы для блоков урока — используй именно их, а не произвольные стили

| Класс | Когда использовать |
|---|---|
| `lesson-card` | нейтральный блок-карточка (подраздел урока) |
| `theory-block` | базовая теория, определения, вводный материал (зелёная рамка) |
| `warning-block` | предостережения, частые ошибки, юридические/этические риски (красная рамка) |
| `law-block` | цитаты законов, нормативных актов (оранжевая рамка) |
| `source-block` | врезка с источниками внутри блока (обычно генерируется `makeContent`, отдельно руками не нужен) |
| `example-block` | практический пример, код, кейс (голубая рамка) |
| `resource-bank` | банк литературы/ссылок в конце семестра (рендерится автоматически через `renderResourceBanks`, руками не пиши) |
| `<span class="definition">термин</span>` | помечай так каждый новый вводимый термин — глоссарий (`renderGlossary()`) собирает их автоматически |
| `<span class="highlight">важное</span>` | акцент на ключевой мысли |
| `<pre data-lang="python">...</pre>` | блок кода; атрибут `data-lang` просто подписывает язык в углу, подсветку делает highlight.js по эвристике |

### Встроенная IDE для практики (`ideBlock()`)

С версии, добавившей интерактивную практику, в `app.js` определена глобальная функция `ideBlock(cfg)`, которая
возвращает HTML-фрагмент со встроенным редактором кода. Используй её прямо внутри template-строки урока через
`${ideBlock({...})}`.

**Важно про порядок загрузки скриптов:** `app.js` теперь подключается в `index.html` ДО `data-*.js`, именно
чтобы `ideBlock()` был доступен в момент выполнения IIFE каждого `data-*.js`. Если снова меняешь порядок
скриптов — не разрывай эту зависимость.

Два режима:
- `mode: 'web'` — живой HTML/CSS/JS-редактор с превью в sandboxed `<iframe>`, работает полностью офлайн.
  Поля: `id` (уникальный!), `label`, `html`, `css`, `js`.
- `mode: 'exec'` — выполнение кода через бесплатный публичный сервис Piston (`emkc.org/api/v2/piston/execute`),
  требует интернет на стороне пользователя. Поля: `id`, `label`, `lang` (`python`, `javascript`, `c`, `c++`,
  `java`, `go`, `php`, `bash`), `starter`.

`id` должен быть уникален по всему сайту (используется как основа для DOM id всех внутренних элементов блока).
Пример использования — уроки `5.2` (`data-websec.js`, web-режим) и `4.3` (`data-crypto.js`, exec-режим).

## 4. Design tokens (кибернетическая тема)

Все цвета — CSS-переменные в `:root` (`style.css`). Основная палитра temы `dark`: фон почти чёрный
(`--bg: #05070b`), акценты — неоновый голубой (`--accent-blue: #2fd0ff`) и неоновый зелёный
(`--accent-green: #00e29a`). Есть готовые тени-свечения `--glow-blue` / `--glow-green` — используй их для
hover-эффектов и активных элементов вместо придумывания новых box-shadow. Шрифт для брендовых
элементов/заголовков — `var(--font-display)` (моноширинный). При добавлении новой темы — скопируй блок
`[data-theme="matrix"] { ... }` целиком и переопредели те же переменные, ничего не удаляя.

## 5. Хранение данных пользователя

Всё состояние пользователя — только `localStorage`, ключи в `LS_KEYS` внутри `app.js`. Никакой сервер сейчас
данные не видит и не может увидеть. Если добавляешь новую фичу с состоянием — заведи новый ключ в `LS_KEYS`
и используй `getLS`/`setLS`, не обращайся к `localStorage` напрямую в остальном коде.

## 6. Авторизация — план на будущее (пока НЕ реализовано)

Осознанно оставлено на потом по просьбе владельца. Когда будет решено делать:

**Ограничение:** бюджета на постоянно работающий сервер нет. Значит, вариант с собственным бэкендом (Go/Node/
Python-сервис + своя БД) не подходит, пока не появится бюджет на хостинг. Реалистичные бесплатные пути:

1. **Supabase (бесплатный tier)** — готовая аутентификация (email/OAuth) + Postgres-БД + REST/JS SDK, без
   написания своего сервера. Хранить там прогресс/избранное вместо `localStorage`. Есть лимиты бесплатного
   плана (проект «засыпает» без активности, ограничение на объём) — уточнить актуальные условия перед
   реализацией.
2. **Firebase Authentication + Firestore (бесплатный Spark-план)** — аналогично, готовая авторизация и
   NoSQL-хранилище с щедрым бесплатным лимитом, полностью клиентская интеграция через JS SDK.
3. **GitHub OAuth Device Flow + GitHub Gist как хранилище** — можно авторизовать пользователя через его GitHub-
   аккаунт и хранить бэкап прогресса как приватный Gist. Требует малюсенькой serverless-функции только для
   обмена `code` → `token` (OAuth не разрешает делать это с чистого клиента из-за `client_secret`) — это можно
   разместить на Cloudflare Workers (бесплатный tier, 100 000 запросов/день) или Vercel/Netlify Functions
   (тоже бесплатные лимиты), не поднимая постоянный сервер.
4. **Clerk / Auth0 (бесплатные tier)** — «авторизация как сервис», готовые виджеты входа, до нескольких тысяч
   активных пользователей бесплатно — избыточно для небольшого учебного проекта, но самый быстрый путь
   внедрения, если важна скорость, а не независимость от вендора.

**Рекомендация по умолчанию, если владелец не уточнил иное:** начать с варианта 1 (Supabase) — там же можно
позже хранить не только логин, но и прогресс/заметки/избранное, полностью убрав зависимость от
`localStorage` конкретного браузера. Перед реализацией — свериться через веб-поиск с актуальными условиями
бесплатного плана (они меняются), поскольку эта инструкция могла устареть.

При реализации: не удаляй текущий `localStorage`-механизм полностью — либо мигрируй данные в облако при первом
входе (аналогично `migrateLegacyStorage()`), либо используй `localStorage` как offline-first кеш поверх облака.

## 7. Чек-лист перед тем, как считать изменение готовым

- [ ] Новый/изменённый `data-*.js` действительно пушит себя в `window.__KERNEL_SEMESTERS` (см. раздел 2)
- [ ] Новые термины обёрнуты в `<span class="definition">`, если должны попасть в глоссарий
- [ ] Проверено в теме `dark`, `matrix` и `sepia` — текст читаем, контраст в порядке
- [ ] Проверена мобильная раскладка (`max-width: 900px`) — сайдбар открывается/закрывается, контент не
      обрезается
- [ ] `sw.js` → `ASSETS_TO_CACHE` обновлён, если добавлен новый обязательный файл, и `CACHE_NAME` версия
      увеличена (иначе Service Worker не подхватит изменения у уже заходивших пользователей)
- [ ] Не добавлен код, требующий постоянно работающего сервера, без явного запроса владельца

## 8. Правило живой документации (обязательно к исполнению)

При любом значимом изменении в проекте (новая фича, новый семестр, смена дизайна, добавление зависимости) —
**в этом же изменении** обнови:

1. **`CHANGELOG.md`** — добавь запись в формате, описанном в начале этого файла (дата, версия, список
   изменений).
2. **`README.md`** — если менялись видимые пользователю фичи, структура файлов или шаги деплоя.
3. **Этот файл (`CLAUDE.md`)** — если менялась архитектура, формат данных, дизайн-токены или появились новые
   правила/ограничения, о которых должен знать следующий агент.

Не откладывай обновление документации «на потом» — следующий агент (или ты сам в другом чате) не будет иметь
памяти об этом разговоре и должен восстановить контекст полностью из файлов репозитория.
